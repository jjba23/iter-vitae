Iter Vitae is a free software project that aims to make it easy and maintainable to generate an attractive, modern and customizable /Curriculum Vitae/ or /resume/ for yourself and to allow you to define the course of your life and career directly in Guile Scheme code.

* The Manifesto

Everyone has the right to create a professional-looking Curriculum Vitae, using free software, without the constraints of proprietary software, lengthy setup processes, or a lack of freedom to modify layouts.

Traditional word processors like LibreOffice or similar can be cumbersome when trying to create a custom CV.

Iter Vitae offers an alternative by embracing the spirit of hacking and freedom, enabling you to customize every aspect of your CV.

With this tool, you can define the content, layout, and presentation of your CV directly in code, making it highly flexible and maintainable.

The tool separates data from its presentation (following the principles of the Model-View-Controller or MVC architecture), so you can focus on the data itself without worrying about formatting or styling.


** Build a Curriculum Vitae for your next 40 years

This tool isn't just about creating a one-off CV — it's designed for long-term use, so you can update and evolve your resume over the years. The software supports multilingual content and is fully extensible, allowing you to add new data entries, customize the design, etc.

Also, version-control your CV code, and enjoy all the benefits. Work with a sane and flexible multi-lingual compatible data model.

Remember that with Guile Scheme, and the Lisp super-powers, everything is extensible, hackable and modifiable at any moment, giving you ultimate control and power.

** On Guix

Iter Vitae is officially distributed via the Guix package manager as ~iter-vitae~. You can alternatively choose to download it from source, useful for developing it or customizing it.
In that case you'll need:

- *Guix*: The Guix package manager will ensure a reproducible working software, and will manage all needed dependencies for you.
-  *Guile Scheme:*  This entire program is written using the official GNU extension language, Guile Scheme.
- Any web browser of your choice (ideally which can also print to PDF)

Check the ~maak.scm~,  and the ~guix.scm~ and  ~manifest.scm~ for more details.

For example, to enter an environment shell with mutastructura temporarily you can use:
#+begin_src shell
guix time-machine --channels=channels.scm -- shell -f guix.scm
#+end_src

You can also chain commands to it:
#+begin_src shell
guix time-machine --channels=channels.scm -- \
     shell -f guix.scm -- iter-vitae --help
#+end_src

In order to view the output this tool generates, we recommend you use a free web browser such as GNU IceCat or Firefox, and after running the tool, open the file at ~./dist/index.html~ or alternately upload and serve it from the web server of your choice.

iter-vitae offers a ~--help~ / ~-h~ flag which will explain all options (also visible in ~resources/help.txt~). You should point iter-vitae to the path to  your configuration file:

#+begin_src shell
iter-vitae --locale nl --file /home/me/documents/my-cv.scm --destination /home/me/documents/dist
#+end_src

** On Podman/Docker

iter-vitae is also available as a Docker container, from DockerHub (also compatible with Podman).

https://hub.docker.com/repository/docker/jjba23/iter-vitae/general

You can also build images of iter-vitae yourself, using ~guix pack~. See the ~maak.scm~ file for more.
To load these tarball images, you can do ~podman load < my.tar.gz~

Then you can run iter-vitae from the container, and bind your local filesystem to give access, for example:

#+begin_src shell
docker container run -v /home/joe:/home/joe \
    docker.io/jjba23/iter-vitae:latest iter-vitae \
    --file /home/joe/me.scm \
    --locale en \
    --destination ./dist
#+end_src

* How to write your CV in Lisp?

Here follows an explanation of all the fields and possibilities that ~iter-vitae~ provides you.

Iter Vitae gives you the power of Lisp to define your CV. That means we mostly work with idiomatic data structures, specially ~list~ and ~alist~ (association lists). Some of those alists contain language-specific content, and as such, we call them ~translation-alist~, e.g.

#+begin_src scheme
`((en . "Software Engineer ⚙️")
  (nl . "Software Engineer ⚙️")
  (es . "Ingeniero de Software ⚙️"))
#+end_src

translation-alists can contain endless amount of translations for every language code that you want to support. If the value should be the same for all languages, simply use the key ~all~, e.g.

#+begin_src scheme
`((all . "Software Engineer ⚙️"))
#+end_src

Some variables have sensible defaults, and as such can be skipped from customization.
You should also look at the defaults for more info: [[file:src/iter-vitae/defaults.scm]]

Also, for a "real-world" example, you can see my own CV: [[file:populus/joe.scm]]

The following variables are read by Iter Vitae to construct a CV:

- ~titles~ is a list of ~translation-alist~ with content for each section's header, in different languages.
- ~document-theme~ is a symbol (e.g., ~'ef-cyprus~) that specifies the visual theme, color scheme, or styling to be applied when the document is ultimately generated. See supported themes section above.
- ~display-name~ is a *required* ~translation-alist~ that represents the person's name.
- ~job-title~ is a *required* ~translation-alist~ that represents the job title to be displayed.
- ~job-title-link~ is an optional ~translation-alist~ that represents the URL to visit when clicking the job title header.
- ~personal-contact~ is an ~alist~ that expects the person's e-mail in the ~emails~ field, and the person's phone number in the ~phone-numbers~ field
- ~personal-links~ is an ~alist~ of optional fields that can contain ~blog~ , ~code~ and ~linked-in~ , all of which are strings.
- ~address-lines~ is a ~list~ of ~translation-alist~ and allows one to display address details, line-by-line.
- ~driver-licenses~ is an optional ~list~ of ~translation-alist~ that outlines your driving qualifications.
- ~interests-hobbies~ is an optional ~list~ of ~translation-alist~ used to describe your hobbies and personal interests.
- ~language-proficiency~ is an ~alist~ that defines the grading scale for your language skills. It maps a language code (like ~en~ or ~nl~) to an ~alist~ of integer levels (e.g., 1 to 4) alongside their localized string descriptions (e.g. ~"Elementary Proficiency"~ , ~"Native"~).
- ~languages~ is an ~alist~ detailing the languages you actually speak. Each key is a language code mapped to an ~alist~ containing a ~name~ (a ~translation-alist~ with the language's display name and optional emoji) and a ~proficiency~ field. The ~proficiency~ field is itself an ~alist~ mapping ~reading~, ~speaking~, and ~writing~ to the integer levels you defined in ~language-proficiency~.
- ~education~ is a ~list~ of ~alist~ data structures detailing your academic background, courses, and educational internships. Each entry expects ~name~ (the institution), ~location~, ~position~ (the degree or course name), ~time~, and ~experience~ (a ~list~ of ~translation-alist~ outlining what you learned or achieved).
- ~short-intro~ is a ~list~ of ~translation-alist~ that acts as your personal summary, biography, or cover letter excerpt.
- ~jobs~ is a ~list~ of ~alist~ data structures detailing your professional experience. Each entry expects ~name~ (the institution), ~location~, ~position~ (the degree or course name), ~time~, and ~experience~ (a ~list~ of ~translation-alist~ outlining what you did or achieved).
